### 2026-10-03: spend-ledger and batch safety review (infrastructure, no method change; before any evaluation run)
- **Race found and fixed**: in the one-at-a-time path a call's reservation was released and its real cost recorded in two separate lock acquisitions; in the gap that spend counted as neither in flight nor spent, so a parallel call could slip past the limit check. `Ledger.record(release=...)` now does both in one step. A failed call gives its reservation back.
- **Batch limit check made strict**: the check before submitting a batch now uses each request's worst-case cost (output capped by `max_tokens`, input at 3 characters per token plus 10%) instead of an expected cost, so the real cost can never pass the limit. If a whole batch's worst case does not fit, it is split into chunks that each fit (a finished chunk costs less than its worst case, so later chunks usually fit more); if not even one request fits, `SpendLimit` is raised and nothing more is submitted. Results already paid for when a stop happens are written to the on-disk cache, so they are never bought twice.
- Tests (offline): 8 threads x 25 calls against a small limit: stop triggered, every real call recorded exactly once, total equals the sum of the file, spend never passed the limit, all reservations returned. A rate-limited call (HTTP 429) is retried with a delay and then succeeds; a permanent 429 is raised after the retries (the client is built with `max_retries=5`, the SDK's backoff). Batch tests: chunking at the limit, resume of an interrupted batch, retry of a failed request.

### 2026-10-03: documented bug fix, a crash on a dropped network connection (made AFTER the rivaroxaban 2017Q4 run and BEFORE any positive-case run)
- **What the owner and I had already seen before this fix**: the rivaroxaban 2017Q4 Arm B run finished (cost $0.5281): all three target PTs (DRUG-INDUCED LIVER INJURY, LIVER INJURY, HEPATOTOXICITY) had **no statistical flag** at 2017-12-31 (route 1), and the Skeptic recommended 132 of the 135 terms it examined. - **The crash**: the rivaroxaban 2018Q4 run stopped during the Skeptic's evidence step with `ConnectionResetError 10054` ("an existing connection was forcibly closed by the remote host"), raised through `requests` from `canary_utils.get_json` while fetching PubMed (`agents/skeptic.py`). `get_json` retries HTTP 429 and 5xx but not a dropped connection. The run's Label Checker batch for 2018Q4 had already been paid ($0.2020) and cached. 2019Q4 had not started. Evaluation ledger total at the stop: $0.730018 (445 calls, 4 batches, all Haiku). The error was shown, not retried silently.
- **The fix** (`net_retry.py`; locked `canary_utils.py` untouched): a dropped connection (builtin `ConnectionError` family such as ConnectionResetError, `requests` ConnectionError and ChunkedEncodingError, the Anthropic SDK's `APIConnectionError`) is retried at most 3 attempts in total with a short backoff (1 s, then 2 s) and the SAME request (same URL, same query, same date limit). Nothing else is retried (HTTP errors, read timeouts and bad data raise at once). If the third attempt still fails, the original error is raised and the run stops: a lookup is never skipped silently and no empty evidence is invented. Applied to every network call on the evaluation path other than the LLM calls: PubMed esearch and esummary (the Skeptic's wrapper), the five RxNorm calls (Drug Resolver), and the batch status poll and the batch result read (the result stream is read completely before any cost is recorded, so a retry cannot double-record a cost). **Batch creation is deliberately not retried by us**: a retry after a lost response could submit the same batch twice and pay twice, so a dropped create is raised and the run stops (the Anthropic SDK's own retries, set to 5 for the pipeline client, still apply underneath; that SDK-level retry is a small residual risk of a duplicate submission, bounded by one batch and inside the $0.50 gap between the $9.50 budget and the $10.00 balance). Local calls (DuckDB, Chroma, the local embedding model, label files) have no network.
- **Tests** (offline, fake errors, no spend): `tests/test_network_retry.py`, 9 tests: two resets then success with the identical request, the date limit and the exact-phrase query kept; three failures raise (no skip) after exactly 3 attempts; non-connection errors raise at once; the failure surfaces through the Skeptic's parallel evidence step; RxNorm retries; batch polling and a mid-stream read failure recover with every request recorded exactly once and one batch submitted; a failed create is raised once and not repeated.
- **Resume check (no paid call possible: the client raised on any call)**: resuming 2018Q4 reuses all 150 Label Checker answers from the on-disk cache (150 of 150 cached, 0 batches sent, 0 ledger rows, $0), the real evaluation ledger was unchanged (still $0.730018), the decisions match the first pass (15 yes, 82 partial, 53 no), and 114 of the 135 Skeptic PubMed lookups were already cached, so only the remaining 21 are fetched. A resume skips the finished 2017Q4 run and continues with 2018Q4. A stop is not a re-run.
- **Runner change (no method change)**: the runner's "clean working tree" check now ignores its own output folder `eval_out/`, so the saved 2017Q4 results do not make a resume refuse to start. Code and config are still checked.

## Post-result exploratory work, part 2: alternative ranking scores (2026-10-03, branch `triage-v2`). Defined BEFORE seeing any result. Illustrative only, NOT validation

- **Motivation**: the previous check (term grouping and reserved slots, logged above) rescued at most 1 of 6 target terms, and the reason found was the ranking criterion itself: chi-squared favours high-count terms, so a rare serious signal such as gabapentin's older-named DRESS term (rank 390, 181 and 271 at 2007Q4, 2008Q4, 2009Q4, below the cap of 150) is buried even though it meets Evans. - **Tested on the cases that exposed the problem**, so any improvement is illustrative and not validation.
- **Three candidate ranking scores, fixed here before any result** (they replace chi-squared in the ranking step ONLY; everything else in triage is unchanged: the Evans flag, a >= 3, the exact on-label drop, the cap of 150; no term grouping and no reserved slots are applied in this part). Every term uses its own drug-level 2x2 table (a, b, c, d) from the Miner at the cutoff, N = a + b + c + d:
  1. **PRR lower bound (95% confidence interval)**: SE = sqrt(1/a - 1/(a+b) + 1/c - 1/(c+d)); lower bound = exp(ln(PRR) - 1.96 x SE), with PRR = (a/(a+b)) / (c/(c+d)). Rank by this value, largest first.
  2. **IC025** (lower bound of the information component): E = (a+b)(a+c)/N; IC = log2((a + 0.5) / (E + 0.5)); IC025 = IC - 3.3 x (a + 0.5)^(-1/2) - 2 x (a + 0.5)^(-3/2) (the standard approximation of the 2.5th percentile of the IC posterior used in BCPNN signal detection). Rank by IC025, largest first.
  3. **Best of both**: each term gets its rank under score 1 and its rank under score 2 (1 = best, among the triage survivors); the combined order sorts by the better (smaller) of the two ranks, then by the worse rank, then by term name. Take the first 150.
  Ties in any score are broken by term name (alphabetical), so every run is deterministic. **No thresholds are tuned and no other score will be tried after seeing results; all three are reported, including any that fail.**
- **What will be reported**: for gabapentin older-named DRESS at 2007Q4, 2008Q4 and 2009Q4, linezolid SIADH and lithium DRESS: the old rank (chi-squared), the new rank under each score, and whether the term makes the cut of 150. On the five evaluation drugs at all 16 cutoffs (the reduced schedule plus the four supplementary gabapentin year-ends): how each final list differs from the locked list (terms swapped in and out), and whether any previously caught target (pirfenidone hepatotoxicity 2015Q4, lamotrigine aseptic meningitis 2004Q4, dasatinib chylothorax 2007Q4) would be lost.

## Post-result exploratory work, part 3: stratified triage and a free retention benchmark (2026-10-03, branch `triage-v2`). Everything below is FIXED before any result is computed. Illustrative only, NOT validation
- **Status, stated first**: post-result exploratory work on branch `triage-v2`, free and offline: no paid API call, no Label Checker or Skeptic run, no new evaluation. It does not change `EVALUATION_PLAN.md`, `eval_config.py`, `canary_utils.py`, `eval_results.md`, `eval_supplementary_gabapentin.md` or anything in `eval_out/`. The locked triage (chi-squared rank, cap 150) stays the default and must keep reproducing the locked output on all 12 saved runs; the new design is opt-in, default off.
- **Why a different kind of remedy**: five earlier remedies failed or barely helped (term grouping; reserved slots for serious events, both as specified and in the "beyond the cut" variant; PRR lower bound; IC025; best of both). All five leave every term competing in ONE global chi-squared-style ranking, so rare terms are crowded out by the very common ones. This part changes the competition itself: terms compete only against terms with a similar number of reports. The cap stays at **150**.
- **Candidate design, "stratified triage" (the only variant; fixed here)**. Survivors S = the terms that are Evans-flagged, have a >= 3 reports and are not named on the label in force (exactly the locked filters). N = |S|. If N <= 150, all survivors are kept (as in the locked triage). Otherwise:
  1. Report-count bands by a (the drug's reports with the term): **B1 = 3 to 10, B2 = 11 to 30, B3 = 31 to 100, B4 = over 100**. n1..n4 = survivors per band.
  2. Proportional quotas: q_b = 150 x n_b / N, turned into whole numbers by the largest-remainder method (ties go to the rarer band).
  3. Rare minimum: R = ceil(0.25 x 150) = **38 slots for B1 and B2 combined**. If q1 + q2 < 38, raise q1 + q2 to 38, split between B1 and B2 in proportion to n1 : n2 (largest remainder), and take the extra slots from B3 and B4 in proportion to their current quotas (largest remainder, never below 0).
  4. Availability: q_b = min(q_b, n_b). Unused slots are given to the bands that still have unselected survivors, in proportion to how many they have left (largest remainder, each band limited to what it has), repeated until all 150 slots are used. The list size is always min(150, N).
  5. Within each band take the top q_b by chi-squared (ties by term name). The final list is the union, ordered by chi-squared.
  **No SOC variant**: there is no complete preferred-term to system-organ-class mapping in our data (the EMA IME file carries an SOC for only 7,846 of about 25,000 terms), so none is built. These numbers are not tuned after seeing results; every result is reported, including failures.

- **Variant P (prune, then cap)**. Remove Evans-flagged terms (a >= 3) that: (1) appear by exact preferred-term name (locked folding, whole words, case-insensitive) in the label version in force at the cutoff; (2) match the fixed non-clinical list below (matched against the whole upper-cased PT); (3) equal (case-insensitive, whole PT) one of the drug's top 3 FAERS indications up to the cutoff. - **Fixed non-clinical list** (rule 2). A PT is non-clinical if it equals one of these (exact):
  DRUG INTERACTION; TREATMENT FAILURE; THERAPEUTIC RESPONSE DECREASED; THERAPEUTIC RESPONSE UNEXPECTED; THERAPEUTIC PRODUCT EFFECT DECREASED; THERAPEUTIC PRODUCT EFFECT INCOMPLETE; TREATMENT NONCOMPLIANCE; CONDITION AGGRAVATED; DRUG USE FOR UNKNOWN INDICATION; PRESCRIBED OVERDOSE; PRESCRIBED UNDERDOSE; UNDERDOSE;

  `^PRODUCT\b` (all product issues); `MEDICATION ERROR`; `\bWRONG\b`; `\bINCORRECT\b`; `OFF[- ]LABEL`; `UNAPPROVED INDICATION`; `^NO ADVERSE EVENT`; `^DRUG INEFFECTIVE` (also "... FOR UNAPPROVED INDICATION"); `^DRUG DOSE OMISSION`; `^EXTRA DOSE`; `^DEVICE\b`; `^EXPIRED (PRODUCT|DRUG)`; `^INAPPROPRIATE SCHEDULE OF` (administration schedule errors); `DRUG DISPENSING ERROR`; `^INTENTIONAL (PRODUCT|DRUG) (MISUSE|USE ISSUE)`.
  Name-only check made before writing this entry (no data computed): none of the target and caught-target terms (both DRESS names, aseptic meningitis, hepatotoxicity, chylothorax, drug-induced liver injury, liver injury, SIADH, hyponatraemia, blood glucose increased, HbA1c increased) matches the list. Plain OVERDOSE, DEATH, DISEASE PROGRESSION and PREGNANCY terms are deliberately NOT on the list.
- **Variant PN (prune plus novelty quota)**: Variant P, plus up to 40 of the 150 slots for novel terms. A pruned survivor is **novel** if (its reports with first-receipt quarter in the last 4 quarters up to and including the cutoff quarter / its total reports a) >= 2 x (the drug's reports with first-receipt quarter in the same 4 quarters / the drug's total reports n_drug). The best 40 novel terms by chi-squared (ties by name) take the quota slots (all of them if fewer than 40); the other slots are filled by chi-squared rank from everything not already taken. No minimum count is added inside the window.
- **Variant PL (prune plus label-aware seating)**: Variant P, then **label distance** = 1 - the highest cosine similarity between the term's embedding and any chunk embedding of the label version in force at the cutoff (the brand label of the RAG index, vectors read from the Chroma collection `labels`, filtered by drug and label date). The term is embedded with the existing local model (bge-small via fastembed) using the query form the Label Checker already uses: query prefix + `"<term lower-cased> adverse reaction"`. Ranks are computed over all pruned survivors: chi-squared rank (1 = largest) and label-distance rank (1 = largest distance). Combined rank = (chi-squared rank + label-distance rank) / 2, lower is better; ties by chi-squared rank, then term name. Top 150 are kept. No term is ever dropped for being close to the label; closeness only lowers its rank. If a benchmark drug has no indexed label version in force at a cutoff, it is reported and skipped for PL and PLN there (all nine benchmark drugs are indexed, so none is expected).
- **Variant PLN (all three)**: PL ranking plus the 40-slot novelty quota. The quota slots are taken exactly as in PN (best novel terms by chi-squared); the remaining slots are filled in PL combined-rank order (ranks computed once over all pruned survivors, not recomputed after the quota terms are removed).

## Post-result exploratory work, part 5, Step 3: Evidence-Weighted Triage (EWT), the exact design (2026-10-04, branch `triage-v2`). Everything below is FIXED before any ranking is computed. Illustrative only, NOT validation
- **Status, stated first**: this is **post-result exploratory work**, free and offline (no paid API call, no Label Checker, Skeptic or Writer run, no evaluation run). It does not change `EVALUATION_PLAN.md`, `eval_config.py`, `canary_utils.py`, `eval_results.md`, `eval_supplementary_gabapentin.md` or `eval_out/`. The locked triage (chi-squared rank, cap 150) stays the default and must keep reproducing the locked output on all 12 saved runs; EWT is **opt-in, default off** (`ewt=True` in `agents/triage_step.py`; code in `triage_ewt.py`).
- **Inspiration and credit**: the WHO Uppsala Monitoring Centre's vigiRank (Caster et al., Drug Safety 2014; Pharmacoepidemiology and Drug Safety 2017), which ranks signals by strength of evidence and not by volume alone. EWT is **our own adaptation** with FAERS fields and **equal weights**; it is not vigiRank and is not called that in any file.
- **Honesty about tuning**: the idea comes from the failure pattern on the development drugs (gabapentin, linezolid, lithium: terms that met the Evans criteria but ranked 181 to 391 by chi-squared). **Development results are therefore tuned evidence, not clean.** The held-out drugs (pirfenidone, lamotrigine, dasatinib, rivaroxaban, atorvastatin, ixazomib) were already used in part 3 (once) and part 4 (second look); here they are a **third look**. **The five fresh drugs (montelukast, voriconazole, docetaxel, bosentan, enzalutamide; list committed in `bd88b30`) are the clean test, run ONCE.** The rules below are fixed now and **will not be tuned afterward**; every result is reported, including failures.
- **Survivors**: the locked ones: Evans-flagged (a >= 3, PRR >= 2, chi-squared >= 4) and the exact preferred-term name not on the label version in force (the locked drop, same matcher). EWT only re-orders and re-selects them.
- **Five components** (a sixth, dechallenge or rechallenge, was dropped by the owner as too patchy; event date and drug start date are not used). Counts are over the drug's reports exactly as the Miner defines them (drug is Primary or Secondary Suspect, latest case version known at the cutoff quarter), at the cutoff:
  1. **IC025**: lower bound of the information component, `IC = log2((a+0.5)/(E+0.5))`, `E = (a+b)(a+c)/N`, `IC025 = IC - 3.3 (a+0.5)^-1/2 - 2 (a+0.5)^-3/2` (the function already in `triage_v2.py`), from the Miner's a, b, c, d.
  2. **Health-professional reports**: reports of the term whose occupation code is MD, HP, PH or RN (CN consumer, LW lawyer, OT other and blank are not health professional).
  3. **Recent reports**: reports of the term whose case was first received in the last 4 quarters up to and including the cutoff quarter (the same first-receipt window as the part-4 novelty rule).
  4. **Distinct countries**: distinct countries among the term's reports; occurrence country, else reporter country (names mapped to codes, "COUNTRY NOT SPECIFIED" and blanks are unknown and are not counted as a country).
  5. **Serious-outcome reports**: reports of the term with an outcome code **DE, LT, HO, DS, CA or RI; OT ("other serious") is excluded**.
  All five are used at every cutoff. Known data limits, not corrected: 2004 has no country data (the component is the same for all terms, so it adds nothing there), 2005 has half; occupation is 75 to 85% filled up to 2010.
- **Score**: each component is turned into a rank among the survivors (1 = largest value; equal values share the average rank). Score = the **plain average of the five ranks** (lower is better). Ties in the score go to the better chi-squared rank, then the term name. **Keep the top 150; the list size is always min(150, survivors).** No weights, thresholds or component choices are fitted or changed after any result. The final list is shown in chi-squared order.
- **Benchmark and metric (the part-3 benchmark, unchanged; `analysis/benchmark_retention.py` functions)**: for each drug and each year-end cutoff 2004 to 2025 with at least 50 Miner reports and a brand label in force, benchmark terms = locked survivors named in an adverse-reactions or warnings section of a later label version within 5 years (same match rule, same exclusion of one-word terms shorter than 6 letters, same A1/A2 ambiguous classes). **Retention** = share of benchmark terms that are in the final list, pooled over the cutoffs where the locked cap binds (survivors > 150), per drug and pooled; secondary: all cutoffs. The caveat from part 3 stands: a label is a lagging, imperfect proxy and the benchmark is biased towards common terms.
- **What "EWT beat the locked triage" means (fixed now)**: on the five fresh drugs, EWT's pooled capped retention is **higher than the locked triage's by at least 3 percentage points, and no caught target (below) is lost.** A difference under 3 points, or any caught target lost, is reported as "did not beat". Per-drug numbers are shown, but no single drug decides.
- **Splits and run discipline**: the five fresh drugs are run ONCE (`analysis/ewt_check.py fresh` refuses a second run once its result file exists). Development (gabapentin, linezolid, lithium) is run first as an implementation check and is labelled tuned evidence. Held-out (pirfenidone, lamotrigine, dasatinib, rivaroxaban, atorvastatin, ixazomib) is labelled third look. If an implementation bug is found, it is fixed without changing any rule here and the fix is logged.
- **Also reported**: (a) the targets, in or out and rank under the locked triage and under EWT: gabapentin older-name DRESS (2007Q4, 2008Q4, 2009Q4), linezolid SIADH 2019Q4, lithium DRESS 2017Q4 (both names); (b) the caught targets must stay in: pirfenidone hepatotoxicity 2015Q4, lamotrigine aseptic meningitis 2004Q4, dasatinib chylothorax 2007Q4 (at those cutoffs the survivors number fewer than 150, so nothing can drop out; later cutoffs of the same terms are also shown); (c) final list sizes and terms swapped versus the locked list at the capped cutoffs of the 15 evaluation cutoffs plus the 2 demo cutoffs, and per benchmark drug; (d) a plain conclusion.
- **Expectation, written down so it cannot be adjusted afterward**: three of the five components (health-professional, serious and recent counts) grow with report volume, so EWT may track chi-squared more than it differs from it; the countries and IC025 components are the ones that can promote rarer terms. I do not know which way the result goes.
